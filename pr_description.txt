Root cause: WebSocket streams lack inactivity timeout checking, which causes hanging streams when the connection silently drops. Furthermore, passive completed children remain labelled live in the daemon due to incorrect registry status resolution.

Fix: Added a 30s inactivity timer in `parseWebSocket` (in `openai-codex-responses.ts`) which is reset on each message, aborting and closing the websocket on timeout. Also introduced `releasePassiveRlmChildSession` in `AgentSession` (in `agent-session.ts` and `daemon-mode.ts`) to cleanly drop RLM tracking of passive children and updated daemon status resolution to require `daemonChild.status === "running"` for a running state.

Validation: Pre-commit checks passed (`npm run check`) and automated tests verified (`npx vitest --run test/suite/regressions/agent-session-passive-rlm-child-release.test.ts` passed).
